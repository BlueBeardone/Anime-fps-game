# Anime FPS Game — Muzzle, Physical Drops and Hover Pickups

Date: 2026-11-20
Status: approved

## Intent

Three feel problems in the current weapon loop:

1. Tracers and muzzle flash start slightly off the barrel.
2. A dropped gun appears instantly and can end up in or below the ground.
3. A picked-up gun snaps into the hands with no travel.

The fix should make the muzzle authoritative per gun, make dropped guns real physics objects that
land on the ground, and make the picked-up gun visibly travel into the player's hands.

## Goals

- Every viewmodel has an explicit muzzle position that effects and tracers use.
- The fallback muzzle calculation uses the bore centreline, not a bounding-box corner.
- A runtime drop is thrown forward and up from the player's chest, falls under gravity, and settles
  on the ground without sinking through it.
- All peers see the same thrown drop (server-simulated, replicated).
- A settled drop no longer blocks player movement.
- On the owner, the picked-up gun's viewmodel starts at the ground gun's world position and eases
  into the hand pose over a short hover.
- Existing pickup authority, ammo round-trip and drop cooldown behaviour is preserved.
- `Anime FPS > Run All` generates all new prefab wiring idempotently.

## Non-goals

- Changing where the hit ray comes from. The ray stays camera-accurate for the crosshair; only the
  visible tracer and flash move to the true muzzle.
- Client-authoritative pickup swaps or drops.
- Moving the actual networked pickup object into the hands before the swap. The hover is an
  owner-side viewmodel presentation so the swap stays instant and server-authoritative.
- Pickup audio, outlines, or authored animations.

## Constraints

- Unity 6000.6.9f1, URP, NGO 2.14.0.
- `Assets/_Project/Editor/ProjectSetup.cs` remains the authoritative generator.
- Existing PlayMode tests must stay green.
- Runtime pickups are spawned only by the server; scene pickups remain static.

## Approaches considered

1. **Server Rigidbody + NetworkTransform (chosen).** Runtime drops get a server-side Rigidbody and
   box collider; a NetworkTransform on the pickup prefab replicates the throw and landing. Idiomatic
   NGO, every peer sees the same motion, and the server owns the result.
2. **Server Rigidbody + hand-written transform NetworkVariables.** Avoids touching the prefab but
   duplicates what NetworkTransform already does and adds a custom interpolation path.
3. **Deterministic local simulation on every peer.** No network traffic, but divergence and
   floating-point differences make the resting place disagree between peers.

Approach 1 wins because the project already uses NetworkTransform for the player and ProjectSetup
already regenerates the pickup prefab.

For pickup travel, two options were considered: delaying the server swap and moving the real pickup,
versus easing the new viewmodel from the ground gun's position. The viewmodel hover was chosen
because it keeps the swap instant, preserves ammo/authority semantics and existing tests, and looks
the same to the player.

## Design

### Muzzle

- `WeaponDefinition` gains `public Vector3 muzzleLocalPosition`.
- `ProjectSetup.ConfigureSlot` computes the value from the viewmodel prefab and writes it into each
  slot. The value is the centre of the forward-most cross-section of the combined renderer bounds,
  expressed in viewmodel-root local space.
- `ProjectSetup` also ensures a direct child `Muzzle` marker exists in each generated viewmodel
  prefab at that local position, so the position is inspectable and editable in the scene.
- `PlayerWeapons.ApplySlot` prefers `definition.muzzleLocalPosition` when it is non-zero; otherwise
  it falls back to `ViewmodelMuzzle.ComputeLocal`.
- `ViewmodelMuzzle.ComputeLocal` still prefers a child named `Muzzle`, but its no-marker fallback
  returns `(boundsCentre.x, boundsCentre.y, boundsMax.z)` instead of the maximum-`z` corner.
- Effects and tracers continue to start at `MuzzleWorldPosition`. The shot ray still starts at the
  camera position.

### Physical drop

- `WeaponPickup.prefab` gains a server-authority, interpolating `NetworkTransform` (generated by
  `ProjectSetup.EnsurePickupPrefab`).
- Server `SpawnDrop` instantiates the pickup at `player.position + up * 1.2 + flatForward * 0.5`,
  initializes ammo, spawns it, then calls `WeaponPickup.Launch(forward * 4.5 + up * 2.2, spin)`.
- On the server, `Launch` ensures a `Rigidbody` and a `BoxCollider` sized from the gun's combined
  renderer bounds, then applies the velocity and a small random angular velocity. Gravity and the
  scene ground do the rest.
- When the body has been nearly still for a short settle window, it becomes kinematic and the
  collider is disabled, so the gun cannot push or block players. The visual keeps its existing spin.
- The existing 0.75 s runtime-drop cooldown still prevents instant re-pickup.
- Scene pickups remain non-physics and static.

### Hover pickup

- `PlayerPickupInteractor` caches the target pickup's world position and tells `PlayerWeapons` to
  start a hover when the incoming swap lands.
- `PlayerWeapons` gains a short hover state: when the active slot's gun changes because of a pickup,
  the freshly instantiated viewmodel begins at the cached world position converted into camera-local
  space and eases to `viewmodelBasePosition` over `PickupHoverSeconds` (0.3 s). Normal kick, reload
  and bolt offsets resume after the hover.
- The ground pickup is still consumed on the server immediately, so two players cannot take it and
  ammo/authority behaviour is unchanged.
- Remote peers see the instant swap; the hover is owner-only presentation.

## Tests

- The muzzle fallback returns the forward centre, not a corner, for an off-centre renderer.
- A named `Muzzle` child still wins.
- After a host pickup swap, the new runtime drop has a Rigidbody, is airborne above the ground, and
  eventually settles above `y = 0` without sinking.
- The existing pickup/ammo/cooldown tests stay green.
